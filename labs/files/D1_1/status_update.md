# Tagger: status update for the operations director

From the data team, to the operations director. Copied to the head of reception.

As you know, we started work on the request urgency tagger in the summer, and since then quite a
lot has happened. The first version used only keyword rules, which worked quite well on the
messages we tried, and the reception team was generally positive about it. Later we tried two
hosted models as well, and we ran an evaluation on a test set of messages that the reception team
helped us to label.

During the last sprint we looked more closely at the test set. We found that some of the
messages in it were duplicates, because the same owner had sent the same message through the web
form and again through the front desk, and some were very old. When we removed these, the set
went from 520 messages to 400, and the critical cases from 112 to 80. This matters
because the catch rate on emergency messages is the number the head of reception cares about
most, and with fewer emergency messages the sensitivity figure is less certain than we would
like. The models seem significantly better than the rules, but we cannot say by how much with
the current set.

We think the best way forward is to label new messages. We estimate that 150 new messages,
taken from the North and East sectors where most livestock owners write from, would be enough
to make the result much more reliable, and that two receptionists could label them in about six
hours in total, three hours each, if they use the labelling sheet we prepared. We have checked
that the messages can be labelled without any owner's personal details leaving the clinics'
systems.

So, to sum up, we would like you to approve six hours of reception time, three hours for each of
two receptionists, before the end of next week, so that we can finish the new test set and come
back to you with a comparison you can decide on.
